版本：V1.6｜2026年9月15日｜用途：在Cursor已开发的现有Demo上增量改版；亦适用于Codex接续开发

本业需包同时用于Cursor和Codex，业务需求、页面交互、场景目录及示例数据共用同一套Markdown/JSON文件。开发工具由使用者选择；实际完成情况必须由运行、计算及交互验收确认。

## 1 本轮怎么交给Cursor或Codex

两种工具共用本包，**本轮从Cursor已开发的现有工程继续修改**。把V1.6文件放入现有工程的需求目录；保留旧版供追溯，明确V1.6为当前版本，不创建第二套网站。

1. 首次接续V1.6时，先读当前工程适用的`AGENTS.md`、本文件第8节及《系统原型定位与实施调研说明_V1.6.md》第1至8节及第10至11节，定位现有综合总览、共用布局、指标抽屉、事项和权限实现。操作示例按需读第9节，实施调研与交付范围读第10至11节。之后只读与当前批次有关的主业需章节和数据记录；已有`AGENTS.md`合并保留工程约定。
2. 先确认现有页面、项目启动方式与数据存储位置，再按第5节分批修改。已有依赖满足需求时直接复用，依赖没有改变时不重装；不因这次业需更新而重建工程、重写全部页面或迁移框架。
3. 后续每批只读受影响章节和代码。投资细化按当前领域、子场景ID、指标ID检索适配对照和catalog；配置数据只取相关结构和记录，不重复载入Excel原文或整份巨大JSON。用户反馈具体问题时按范围修复，并检查受影响公共能力。
4. 每批完成后检查相关交互、数值和页面截图，保留工程明确要求的检查；没有具体剩余风险时，不反复执行全量测试、构建或录屏。最终汇总实际验收记录和未完成项。

Cursor和Codex都可使用第8节指令。可用模型、按钮位置和运行能力以实际环境为准；本交接不要求切换工具、购买服务或安装特定插件。

## 3 产品必须保持的主线

一级导航顺序固定为：**综合总览、投资管理、资金管理、产权管理、国际化业务、工程项目管理**。固定资产投资管理与股权投资管理在投资管理页面内以页签切换，不作为侧栏子菜单。导航次序改变不要求重编既有页面编号、对象ID或路由。

侧栏底部增加独立的“系统配置”入口，内部页面标识P76，路由`/settings`；它与上方七个业务入口分区排列，不作为第七个监管领域。顶部“监管工作台”入口汇聚当前用户待核查、待整改、待复核及督办事项。共用数据追溯和业务关联从指标、对象或事项上下文进入。P71—P79只用于研发定位，页面标题、按钮、提示和导出内容不得显示这些编号。

平台是从总部及所属单位开展监管的工作台。用户应能从组织及指标找到对象，沿业务链查看上下游关系，解释规则为何命中，打开对应材料，再开展本平台的核查、整改和复核。源系统的投资审批、招采、签约、付款、记账、正式产权办理和责任追究只展示事实、结果及来源。

需要同时实现三种进入路径：

| 进入路径 | 用户要获得的结果 |
|---|---|
| 组织及指标穿透 | 从海油工程总部到二级、三级单位及项目/资产/账户等末端对象，查看构成和业务明细 |
| 业务链及对象联动 | 从同一投资项目、资产、被投企业、合同、付款或产权事项，查看关联领域中的同一对象及依据 |
| 场景及规则追溯 | 从阶段或专题进入场景，查看适用条件、口径、阈值、版本、命中事实及材料位置，进入核查整改 |

组织管理树与法人/产权关系分开。二级直管项目直接挂接，不补造三级；被投企业不因有股权关系自动进入管理组织树。对象缺少关系时显示缺口，不构造虚假链路。

### 3.1 首页直接完成阶段选择

领域首页顺序为“标题及全局筛选—领域重点指标—横向肩形箭头/专题—场景执行清单及对象事项”。固定资产、股权、产权、工程四领域都在监管总览首页中间直接显示可点击的横向肩形箭头。每个箭头只放**阶段名称＋未关闭事项数**，名称完整可读，不放对象数、场景数、数据覆盖、进度百分比或状态堆叠。

点击任一箭头，直接更新本页下方的场景执行清单及其对象、事项。清单提供监测对象、命中对象、未关闭、本期已整改闭环、逾期整改数五个数量入口。没有先切换“流程监管”Tab或进入矩阵的前置步骤。详细核查表、项目时间线或阶段资料作为选中阶段下的可选展开内容，不替代首页箭头和清单。

全局组织、含下级/仅本级、期间及截至日改变时全页按同一口径重算；阶段及阶段子视图仅筛选下方区域。顶部KPI明确标注“当前组织及期间·领域范围”，不随阶段点击偷偷变成阶段KPI。下区显示当前阶段标签，可清除恢复该领域全部阶段；切换全局范围后仍适用的阶段可保留并重算，无对象时显示具体提示。

固定资产八阶段依次为：**储备谋划、可研论证、决策审批、设计概算、采办管理、建设实施、验收投用、运营及后评价**。“运营及后评价”下区提供“资产运营/投资后评价”子切换，默认资产运营；投用后资产持续运营，后评价按适用条件及评价时点开展，不能实现为先完成后评价才能运营。股权、产权、工程节点名称及条件性、并行关系按完整业需V1.6及对应模板，不自行编造业务硬流程。资金继续使用专题，国际化继续使用地区/事件和影响对象。

箭头顺序表达业务监管视角，不等同所有项目必须串行经过每一节点。工程允许设计、采购、建造等并行；条件性节点按对象适用性显示，说明位于条下或选中阶段的详细区域。已完成或历史阶段只要仍有关联未关闭事项，节点和下方清单就保留这些问题，不仅取对象当前阶段。

### 3.2 指标点击打开P71大抽屉或弹窗

点击首页指标卡默认打开P71大抽屉或大弹窗，保留背景首页及其状态。浮层顶部显示指标、单位、期间、截至日、当前范围及关闭入口；左侧为“海油工程总部—二级单位—三级单位—项目”的可展开树，右侧显示选中节点的指标值、目标/偏差、分子分母、构成和对应业务明细。账户、资产、被投企业等按指标实际末端对象接续；缺层按真实关系跳过。

选择树节点只改变浮层中的指标范围，不修改背景页全局组织。右侧明细可继续查看数据追溯P78、业务关联P79及证据，保留返回P71的节点和展开状态。关闭浮层或完成返回后，背景页面的组织、期间、阶段/子视图、清单筛选、页码、滚动位置保持原样。保留P71页面编号；允许直接链接作为补充入口，但不以整页跳转替代指标卡的默认浮层体验。

### 3.3 五个数量的统计边界

观察归属统一按业务窗口结束日`window_end`落入所选期间（含端点），且评估取得时间不晚于截至日（按主文的业务取得/生效时间口径，不能用实际操作日志`recorded_at`替代）；季度或滚动窗口不按重叠月份拆分分摊。监测记录按实际评估关联的阶段进入清单，不因catalog把场景关联到多个阶段就自动铺满监测对象。有效历史命中即使最新评估正常仍保留；只有确认误报等有效排除才移出命中。人工核查有明确线索可以计命中，无结论显示“—”。整改截止日缺失显示“缺期限”，不当作未逾期。

| 数量 | 统计与点击要求 |
|---|---|
| 监测对象 | 当前范围内已实际评估至少一条适用规则或已完成人工核查的唯一对象；按对象类型＋对象ID去重。应评估与已评估分开，部分规则完成仍显示部分覆盖；点击查看监测记录与缺口 |
| 命中对象 | 当前观察期自动规则命中或人工评估发现明确线索的唯一对象；含已整改闭环的命中历史，确认误报并排除的不计入；同一对象多次命中去重，按对象类型显示并可查看依据 |
| 未关闭 | 当前范围截至日状态未关闭且未排除的唯一risk_id；进入同一事项清单 |
| 本期已整改闭环 | 当前范围内所选期间复核通过关闭且截至日仍为closed、close_reason=rectified的唯一risk_id；整改提交、待复核、已排除均不计入 |
| 逾期整改数 | 当前范围内已进入整改责任范围、截至日仍未关闭（含待复核）且超过有效整改截止日的唯一risk_id；待复核不自动停表；核查或复核其他办理SLA超期不混入 |

资产运营子视图默认按资产数，投资后评价子视图按项目数；末阶段箭头将两者的未关闭事项按risk_id合并去重。未关闭/逾期整改数是截至日存量，本期已整改闭环是期间内完成且截至仍关闭（close_reason=rectified）的数量，不用“本期已整改闭环÷（未关闭＋本期已整改闭环）”计算闭环率。

核查、复核等其他办理SLA超期在监管工作台单列，不计入上述第五数。

场景行、阶段汇总和领域汇总各自按所属范围去重，不能直接相加场景行或阶段行形成上级数。项目、资产、付款等不同类型不混算成一个模糊“对象总数”；按主文明确的类型或分项展示。历史阶段问题和跨阶段关联按规则/事项关联纳入，不因项目已进入下一阶段就消失。

### 3.4 全平台采用统一蓝色主题

本Demo面向国央企总部监管人员，视觉定位为稳重、精致、清晰的企业管理系统。高端感通过统一排版、适度留白、清楚的层级、整齐数字和细致交互实现。综合总览、六业务领域、监管工作台及共用详情全部使用同一套主题和组件。

| 元素 | 设计要求 |
|---|---|
| 一级侧栏 | 深蓝`#0B1F3A`；默认文字`#E7EFFA`、15px，选中白色。展开宽度248px（可在240—264px内统一调整），`flex: 0 0 248px`，不被主区挤压；固定资产在股权上方，底部为系统配置 |
| 主色及交互 | 主蓝`#1D5FD1`用于主要按钮、链接、选中指示及重点业务数据；交互悬停、键盘焦点和禁用状态分别设置 |
| 页面与卡片 | 页面浅灰蓝`#F3F6FB`，卡片白色`#FFFFFF`，细边框和轻阴影；保持统一圆角、卡片间距和内容对齐 |
| 文字与数值 | 深色正文清晰可读；金额和百分比位数一致，金额列右对齐，单位及期间明确；不用装饰性字体或小号浅灰文字承载关键内容 |
| 指标与流程 | KPI突出值、单位和必要比较；横向肩形箭头继续保持阶段名＋未关闭数，选中状态用蓝色边框或描边，监管风险状态仍使用独立红黄语义 |
| 图表与详情 | 常规比较采用有限层次的蓝色系列；风险红、黄、正常绿、未评估灰分别配文字/图标。指标浮层、组织树、场景表、规则、证据和整改窗口沿用统一视觉 |

蓝色表达品牌及交互，不表示风险正常。不得把高风险改成蓝色、仅靠色彩区分状态，或把选中阶段的蓝色误当成风险等级。首页以可用的监管工作台为核心，不添加无实际监管用途的旋转地球、发光网格、霓虹描边、满屏渐变或装饰动画。不得编造官方标识或授权背书。

在1440×900优先验证完整业务入口、重点指标、流程/专题和场景清单的衔接。四流程领域首屏能看到横向箭头；阶段名称清晰完整，空间不足使用受控横向滚动，不压成难读的小字或复杂折线。P71和其他浮层的标题、关闭、树和明细均可操作。保留AC01至AC70既有要求，补充AC71至AC100的侧栏、配置、权限、文案和AI验收；各批按改动影响选择检查，不要求每次重跑全量。

### 3.5 侧栏和页面文案必须在共用组件修复

布局采用侧栏固定宽度、主内容`flex: 1; min-width: 0`。侧栏内部图标固定宽度且不缩小，图标与文字间隔8—12px；文字容器设`min-width: 0`，正常展开状态保证七个标准菜单名称及“系统配置”完整可读。个别超长自定义名称可在菜单内部换行或省略并提供完整名称提示，不得让文字溢出菜单、侵占主区或通过极小字号解决。侧栏的上部菜单可独立滚动，底部配置入口始终可达；顶部品牌也需在侧栏宽度内排版。

业务字段统一使用“一级监管场景、监管子场景、场景描述、管控要求、监控指标、监测规则、执行方式、规则依据、计算依据、来源记录”等语义名称。原文件名、行列、`original_columns`及研发字段仅存审计元数据，不能自动生成业务字段标签。指标和对象稳定ID可在技术定位或必要编号位置保留，但页面标题、按钮不得拼入P71、P78等内部页面编号。

页面统一标题为“海油工程｜穿透式监管平台”；业务主体按“下属二级单位A/B/C”“下属三级单位A1”“境外分支机构A2”等匿名命名，保留原组织和对象ID。业务界面不出现“演示二级单位”“演示项目”或“演示数据重置”；必要入口改为“数据说明”“重置业务办理状态”“重置配置”等规范名称。真实数据属性在集中数据说明中写明“本系统当前采用合成样例，用于功能验证，不代表海油工程真实经营数据”；AI面板另明确其真实连接状态。不能通过去掉“演示”二字冒充真实海工事实。

### 3.6 系统配置必须有可操作页面

系统配置固定放侧栏底部，进入`/settings`后有六个Tab：

| Tab标识 | 页面名称 | 最低可操作内容 |
|---|---|---|
| users | 用户与权限 | 用户、角色、菜单和操作权限、授权组织范围、本级或含下级、数据范围预览及保存 |
| scenarios | 监管场景 | 一级监管场景与监管子场景维护，新增/编辑/停用，归属领域、阶段、适用对象、责任部门和版本 |
| rules | 监测规则 | 规则条件、数据前提、执行方式、适用范围、阈值/边界、结果说明、试算、发布及历史版本 |
| indicators | 指标管理 | 指标名称、单位、计算公式、输入字段、汇总方式、频率和口径、关联子场景、显示位置及试算 |
| ai | AI分析设置 | 场景能力、允许材料/数据、预设分析任务、证据要求、连接状态和权限；无真实模型时明确样例分析模式 |
| data | 数据与运行 | 数据来源目录、字段映射、数据覆盖与准备情况、导入预览、保存状态、集中数据说明、重置业务办理状态及重置配置 |

六个Tab均要有表单/列表/详情及保存后的可见结果，不做只有菜单或“开发中”的空壳。账号密码、真实密钥、实际对外连接不作为本Demo前端配置内容。前端权限用于验证产品行为，不等同真实后端安全控制。

监管子场景是最小业务分类，不再向下建立“子子场景”。一个子场景可以有多条监测规则；一项指标可以关联多个子场景，不为复用指标复制出多个互相不一致的定义。指标公式和汇总口径属于指标定义；业务目标、预警阈值、触发方向、边界条件属于对应目标/规则配置，不能混成一条公式。规则和指标变更经保存草稿、校验/试算、发布后按生效范围/日期使用；历史评估保留当时版本，不用新阈值覆盖过去结论。自动计算定义必须试算通过；专业核查支撑模板校验材料清单、责任人、适用条件和引用完整性，不要求自动算出专业结论才能发布。没有本期业务对象时，可使用明确标为测试输入的合法数据完成校验，不生成实际业务记录或监测结果。

配置与业务使用同一套服务和持久化。刷新保存配置及业务修改，保存失败有明确提示；“重置业务办理状态”只恢复核查整改等业务办理状态，不清除用户配置；“重置配置”单独说明范围并确认后执行。停用已有场景或指标保留历史关联和结果，不物理删除历史记录。配置新增不自动伪造监测结果。导入配置先校验稳定ID与引用，预览新增、变更和冲突后再应用；拒绝孤立引用和静默覆盖。

### 3.7 权限必须作用于整个查询链

总部相关人员按授权查看总部及所有下属单位；所属单位人员只能访问本单位获授权的范围，本级/含下级由授权明确。单位A的含下级授权可以覆盖其A1和A2，不能看到单位B、C。系统管理员的配置维护权限不自动带来全部业务数据权限。

同一授权范围作用于菜单、组织选择树、KPI分子分母、图表汇总、场景五数、列表、对象详情、业务关系、证据、导入/导出及AI分析，不仅隐藏组织树节点。直接路由访问、搜索对象ID、打开已复制链接也需检查授权；关联到范围外对象时，不展示其名称、金额或其他受限信息。处理跨领域同一事项时仍使用统一risk_id，但只展示当前用户有权看到的上下文。

身份或授权变化后重新建立合法的全局组织范围，清理此前抽屉、详情、查询缓存和AI上下文，不能留存上一个总部用户的明细。当前角色和可看范围在界面可理解地显示；角色切换作为验证能力保留，但不称为已实现正式登录或后端鉴权。

### 3.8 区分规则能力与业务数据状态

按投资底稿逐项适配的三类执行方式组织实际规则：结构化自动识别、线索识别与人工复核、专业核查支撑。AI是否辅助按具体材料和任务确定，不把整个线索识别类别等同AI运行。具体字段值读取本版catalog，不用旧40/10/3统计推断自动化程度。采用人工方式的事项可以在线分派、关联材料、记录结论和跟踪整改，不等于不能进入监管平台。

每个对象×规则实例分开判断三件事：①当前业务是否适用；②所需结构化数据或材料是否准备完成；③是否已执行及结论。没有发生该类业务、规则不适用、待数据接入、缺少某份材料、待人工核查、已核查无异常和已发现线索须分别显示；不能统一呈现为“数据不足”，也不能把“不适用”或“未核查”计为合规。

首页只选已具备可靠输入、能解释计算和监管用途的重点指标，完整38项原指标仍在配置目录保留。对暂未具备数据的指标在指标配置/数据来源页说明具体前提，不用几十张缺数据KPI占据首页。可规范中央企业常态数据的展现和补充正常业务样例，但不能通过把异常改成正常来美化结果；本包金额、8件未关闭基准及已约定事实不得随意改写。样例中的异常是待核查线索或管理偏差，不能直接写成已确认违法违规或实际损失。

### 3.9 AI浮动入口与上下文分析

右下角设置“AI分析”浮动入口，点击打开侧边分析面板；入口不遮挡表格操作、分页、提交及关闭按钮。从领域、指标、对象、子场景或规则进入时携带当前组织授权、统计期间、截至日、当前指标/对象/规则、已发布版本和可访问证据。支持“解释当前指标”“梳理命中依据”“对比材料差异”“建议核查问题”等预设任务，给出可点击的事实/材料位置、结论边界和建议。

没有连接真实模型时，面板清楚标注“预置分析”，点击可查看支持任务及实现范围，设置页说明未连接模型服务；只对已配置且具备事实支撑的任务输出内容，任意问题不伪装成即时模型回答。分析不能跨越权限，不能自行认定违法违规、替代专业估值/减值判断，不能自动发布配置、关闭监管事项或执行源系统业务。切换用户后清除不再有权访问的历史分析上下文。

### 3.10 修复指标与计算依据串用

当前版本曾出现点击“投资计划执行率”却展示EAC偏差公式的反馈，必须检查共用详情是否按对象套用了固定示例。指标值、定义、公式、输入、结果、来源记录及目标阈值均绑定当前指标和查询上下文。

计算/追溯查询至少区分`indicatorId + orgNode + period + asOf + definitionVersion + configVersion + dataVersion + authScope`；稳定对象ID也要进入明细查询。不得只按对象查一份固定依据，也不得把不同指标共用的一组演示文本当结果。
