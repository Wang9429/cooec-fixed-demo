## 2 本版设计判断

以下是结合已查阅资料、海工业务和本轮用户意见形成的产品设计，不是厂商原页面的复刻。肩形箭头、指标浮层及五数口径是本Demo的明确需求，不宣称已经在上述厂商产品中逐项验证。

| 设计重点 | 本Demo具体结果 | 验证重点 |
|---|---|---|
| 监管入口清楚 | 七个业务侧栏负责领域监管，底部P76承接系统配置，顶部P77监管工作台负责共用核查督办 | 业务执行仍在源系统，本平台核查和整改可操作 |
| 首页直接选阶段 | 四流程领域首页中间为横向肩形箭头，箭头仅阶段名＋未关闭数 | 点击直接联动下区，不需要先切流程Tab或矩阵 |
| 指标保持上下文 | 指标卡打开P71大抽屉或大弹窗，左组织树、右指标构成 | 树选择不改背景全局组织；关闭恢复背景状态 |
| 范围明确 | 顶部KPI为当前组织及期间的领域范围，下区为选中阶段范围 | 全局筛选改全页，阶段及子视图只改下区 |
| 场景执行可核对 | 下区显示监测对象、命中对象、未关闭、本期已整改闭环、逾期整改数 | 对象和事项分开去重，观察期与截至日口径可查 |
| 数值有出处 | 指标结果—计算构成—业务记录—凭据/材料逐级追溯 | P78展示记录和材料，未知来源如实说明 |
| 横向跨领域 | 投资、资产、被投企业、产权、合同、付款、工程、事件按依据关联 | P79围绕同一对象，使用同一risk_id和稳定业务ID |
| 预警能够办理 | 认领核查、补充依据、整改跟踪、督办、复核退回及通过 | 只有复核通过且截至仍关闭（close_reason=rectified）才计入符合期间的闭环数 |

页面采用可读的浅色工作台。综合总览的单位×领域风险矩阵可继续用于总体定位；领域首页的阶段选择不依赖阶段×场景矩阵。正式审批、签署、付款、资产处置及记账仍由业务系统执行，本平台呈现相关事实、规则和证据。

## 3 一级导航及四领域流程入口

一级顺序：综合总览 → 投资管理 → 资金管理 → 产权管理 → 国际化业务 → 工程项目管理。投资管理在页面内容区用页签切换固定资产投资管理与股权投资管理，默认固定资产；侧栏不展开这两项。显示顺序不重编原页面编号及业务ID。侧栏底部另设“系统配置”P76，路由/settings，顶部保留监管工作台P77；P78数据追溯和P79业务关联从当前指标、对象或事项进入。

| 领域 | 监管总览首页中部 | 补充交互与适用边界 |
|---|---|---|
| 固定资产投资 | 八个肩形箭头：储备谋划、可研论证、决策审批、设计概算、采办管理、建设实施、验收投用、运营及后评价 | 末阶段下区默认资产运营，支持切投资后评价；运营持续开展，评价按时点和条件开展 |
| 股权投资 | 八个肩形箭头：尽职调查、估值论证、决策审批、协议交割、出资履约、投后治理、收益价值、评价与退出 | 分期出资、治理和收益可并行；末阶段后评价与退出事项分别查看，不要求投资必须退出 |
| 国际化 | 地区/航线事件、价格窗口、受影响项目及敞口专题 | 沿用地区、事件与业务影响组织，不套投资流程 |
| 资金 | 资金计划、账户与集中、收支支付、项目回收、出资支持等专题 | 沿用资金专题监测，不套投资流程 |
| 产权 | 先选择事项类型，再显示该类型的肩形箭头 | 产权登记、产权转让、企业增资、无偿划转、清算注销五类模板及节点名称按主文和seed；不将所有事项都从产权登记开始，不强制相同审批/评估/交易程序 |
| 工程 | 九个肩形箭头：承揽评审、合同策划、设计管理、采购分包、建造实施、运输安装、交付验收、结算收款、质保收尾 | 按工作包显示设计、采购、建造、运输安装等并行；收款、变更、质量及HSE按适用关系贯穿 |

四流程领域均在监管总览首页直接选阶段。其他监管视图可保留，但不得把“流程监管”“事项流程监管”“履约流程监管”等Tab设为使用首页阶段清单的前提。详细核查表、阶段材料、项目时间线和完整阶段关系可在当前选择下展开或进入详情。

箭头只承担选择阶段和显示未关闭数。条件性、并行、重复发生或不适用的说明放在条下提示和下方详情中；箭头排列不构成刚性审批链。历史或已完成阶段的未关闭问题依然在该箭头数量与清单中显示，不按对象当前所在阶段把历史问题隐藏。

参考1440×900桌面视口。以下是页面布局说明，尚不是本平台截图。

| 位置 | 组件 | 内容与点击结果 |

| 页面标题下 | 领域名称、当前范围说明及必要视图入口 | 明示含下级/仅本级；默认监管总览 |
| 第一排 | 4至6张领域KPI卡 | 执行率84%、预计超概项目、低利用率资产净值占比60%、未关闭2等；点击打开P71指标浮层 |

| 箭头下 | 当前阶段标签及适用说明 | 可清除；选末阶段出现资产运营/投资后评价子切换；并行或条件说明在此显示 |

| 可选详情 | 规则、对象、事项、依据、详细核查表 | 随选中场景或数量展开，返回保持阶段及清单状态 |

八个阶段在1440×900下使用单行横向肩形箭头、完整可读名称和明确点击范围。工程九阶段同样采用简单横向条。可以调整条内留白、箭头肩宽和两行文字排布，不把每箭头扩成多指标卡，也不默认改成多行节点矩阵。较窄视口的适配要保留完整名称与选中状态；本版桌面验收不能依赖滚动才找到流程。

阶段名和未关闭数是箭头内仅有的业务信息。例如“建设实施／未关闭1”，点击后展示FA-S20、R01及相关项目；不是在箭头中再显示项目数、场景数、完成率和覆盖率。未关闭0不代表正常或已经全覆盖，监测、命中及资料不足在下区说明。

“运营及后评价”箭头将所关联的未关闭事项按risk_id合并去重。默认资产运营子视图按资产类型统计，进入AS001、来源项目FA-P002、季度利用率依据及R02；切投资后评价按投资项目统计。两视图不是先完成后评价才能运营的串行节点。

## 5 指标卡与P71大抽屉/弹窗

点击首页KPI卡后，P71以足够宽的大抽屉或大弹窗叠加在当前页面上，背景首页保持原样。默认交互不是离开首页进入独立指标页；P71编号和可选直接访问能力可以保留。

| 浮层区域 | 展示与交互 |
|---|---|
| 顶部 | 指标名称、单位、期间、截至日、口径版本、数据状态和关闭入口 |
| 左侧组织树 | 海油工程总部—二级单位—三级单位—项目，节点带指标值；可展开、收起并选择，缺层按真实管理关系跳过 |
| 右侧上部 | 当前节点指标、分子分母、目标/阈值、偏差、覆盖情况；跟随左树选择同步更新 |
| 右侧主体 | 指标构成及对应业务明细；可继续查看下级比较、趋势和口径，构成不能代替左侧组织树 |
| 深入查证 | 业务记录、P78来源、证据和P79关联对象入口；深入后可回到原P71节点及树展开状态 |
| 关闭 | 恢复背景的组织、期间、截至日、阶段及子视图、筛选、页码和滚动位置 |

浮层初始范围继承点击来源；树内切换节点只更新浮层，不改背景全局筛选。不同指标按实际末端对象查看项目、资产、被投企业、账户或产权事项，管理组织与产权关系不能混为一棵树。

固定资产执行率示例：点84%卡片打开P71，左树查看总部84%、下属二级单位A/下属三级单位A1/FA-P001的80%，下属二级单位B直接挂FA-P003的90%；右侧解释分子4800+3600、分母6000+4000。继续查FA-P001预计完工偏差18%时可在右侧看到11800与有效概算10000，再进入来源记录。

P78的数据追溯采用清晰的逐级列表或分层面板：

| 层次 | FA-P001示例 | 核查重点 |
|---|---|---|
| 结果 | 预计完工偏差18% | 指标、期间、对象、数据完整性 |
| 计算 | EAC11800，对比有效概算10000 | 比较版本和金额口径一致 |
| 构成 | 已入账4800、未入账600、合同剩余3600、变更800、未签剩余2000 | 没有漏项和重复计入 |
| 来源 | 模拟入账、合同/变更/估算依据及批准概算材料 | 日期、单位、金额、出处和模拟性质 |

已入账成本可关联模拟会计凭证，未来估算关联预测说明；不为所有金额统一生成“凭证号”，不将追溯做成无明细示意图。

## 6 场景执行清单与五数

清单必须表达“哪些对象实际接受了何种监测、哪些命中、哪些仍未关闭、哪些本期复核关闭、哪些整改逾期”。每个数量旁的类型和期间可核查，点击对应唯一记录列表。场景行下可查看规则、适用对象和业务依据；详细执行记录可选展开。

观察归属统一按业务窗口结束日`window_end`落入所选期间（含端点），且评估取得时间不晚于截至日（按主文的业务取得/生效时间口径，不能用实际操作日志`recorded_at`替代）；季度或滚动窗口不按重叠月份拆分分摊。监测记录按实际评估关联的阶段进入清单，不因catalog把场景关联到多个阶段就自动铺满监测对象。有效历史命中即使最新评估正常仍保留；只有确认误报等有效排除才移出命中。人工核查有明确线索可以计命中，无结论显示“—”。整改截止日缺失显示“缺期限”，不当作未逾期。

| 数量标签 | 统计口径 | 去重与点击 |
|---|---|---|
| 监测对象 | 当前范围已实际评估至少一条适用规则或已完成人工核查；仅计划纳入或未评估资料不计入 | 按object_type＋object_id；分项目、资产等类型，查看实际评估与缺口 |
| 命中对象 | 当前观察期自动规则命中或人工评估发现明确线索的对象，保留已整改闭环的命中历史；确认误报并排除不计入 | 按object_type＋object_id；同对象多规则命中不重复，查看依据及后续状态 |
| 未关闭 | 截至日仍未关闭且未排除的事项 | 按risk_id；查看当前状态与证据 |
| 本期已整改闭环 | 所选期间经复核通过关闭，且截至日仍为closed、close_reason=rectified的事项 | 按risk_id；查看复核通过记录；提交整改、待复核、排除不计入 |
| 逾期整改数 | 已进入整改责任范围、截至日仍未关闭（含待复核）且超过有效整改截止日；待复核不自动停表 | 按risk_id；未关闭子集，查看整改期限及调整历史；其他核查/复核SLA超期在工作台单列 |

应评估对象与已监测对象分开表达。完成一条规则不等于对象全部规则已经覆盖，显示“部分覆盖”及未完成范围。不同类型对象不能简单相加成一个“项目数”；资产运营子视图使用资产数，投资后评价子视图使用项目数。

场景行、阶段及领域汇总各自重新去重。同一risk_id跨场景、跨阶段或跨领域出现不能重复相加。未关闭/逾期整改数是时点存量，本期已整改闭环是期间完成且截至仍关闭（close_reason=rectified）的数量，不能用“闭环÷（未关闭＋闭环）”推出闭环率。

全局组织或期间变化改全页，下区选阶段只改下区。顶部KPI始终标明当前组织期间的领域范围；下区注明阶段、子视图、对象类型、观察期和截至日，避免同屏不同范围的数字被误认为应当相等。

首版截至日选择仅提供已有完整快照2026-06-30，期间按提供事实选择，历史事件窗口独立。监管操作业务生效日期默认演示截至日，实际操作时间另记`recorded_at`，同日`sequence`排序，`closed_at`使用演示业务日期，保证演示关闭正确进入本期统计。若后续开放其他快照，应重建对应时点状态及余额。期间切换按评估/观察记录判断，不以`first_detected`不在期间为由简单排除当前命中；AC64不要求任意历史截至日。

## 7 业务关系与监管工作台

### 10.4 AI与指标抽屉的组合

右下“AI分析”按钮48px、距边24px，存在固定操作栏时上移。右侧面板420至480px，顶部为当前授权范围，其下为快捷任务、问答与材料引用。指标抽屉打开期间调用AI，继承该树节点而非背景总部；再打开证据时采用统一浮层顺序，Esc只关最上层，返回原节点。

回答结构保持“事实—依据—待核查问题—建议”。数值直接引用当前指标计算结果，状态引用当前统一事项状态，不能用常量句子复述已变化的数据。未接真实模型时面板简短标“预置分析”，设置页解释支持范围；材料引用可打开对应台账字段或证据，普通解释没有真实材料就不编造页码。
